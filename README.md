# Handoff: 룰메이트 (Rulemate) B2C 웹 서비스

## Overview
룰메이트는 사용자가 **직접 정한 조건(규칙)**으로 매일 종목을 걸러 보여주고(‘내 조건 충족 종목’), 공시·뉴스를 알려주고, 계획 → 산 기록 → 판 기록을 매매일지에 남겨 규칙을 고쳐 나가도록 돕는 **PC 우선 웹 서비스**입니다.

- 주문·자동매매·증권사 연동 **없음**. 주문은 사용자가 증권 앱에서 직접 합니다.
- 종목 추천·수익 보장·운영사 점수/순위 **없음** (법적 제약 — 아래 “문구·컴플라이언스 규칙” 필독).
- 대상: 비개발자(블록), 수식 사용자, 개발자(스크립트). 세 방식은 같은 규칙 데이터를 다르게 편집할 뿐입니다.

## About the Design Files
`design/` 폴더의 파일은 **HTML로 만든 디자인 레퍼런스(동작하는 프로토타입)**입니다. 프로덕션 코드로 그대로 복사하지 말고, 아래 권장 스택에서 **같은 화면과 동작을 다시 구현**해 주세요.

- `design/Rulemate B2C.dc.html` — 브라우저에서 바로 열면 동작합니다(같은 폴더의 `support.js` 필요). 템플릿(HTML, `{{ }}` 바인딩) + 하단 `class Component` 로직(상태·계산식·샘플 데이터)으로 되어 있어 **계산식과 문구의 정답 소스**로 쓰세요.
- `docs/Rulemate PRD.dc.html` — 기능 범위·우선순위(P0/P1)·계산 규칙·법적 제약 문서. 브라우저에서 열람/인쇄 가능.
- `data/*.json` — 프로토타입에서 추출한 조건 사전·가상 종목·디자인 토큰. 코드에 하드코딩하지 말고 이 파일을 시드 데이터로 쓰세요.

프로토타입 우측 Tweaks(호스트 기능)의 `demoState`(정상/불러오는 중/결과 0개/장 마감/데이터 지연/오류)는 **화면 상태 확인용**입니다. 실제 앱에서는 데이터 상태에 따라 자동으로 결정됩니다.

## Fidelity
**High-fidelity.** 색·타이포·간격·문구·인터랙션이 최종안입니다. 픽셀 단위로 재현해 주세요. 단, 종목·가격·지표 값은 모두 **가상 데이터**입니다.

## 권장 스택 & 단계
기존 코드베이스가 없으므로 다음을 권장합니다(변경 가능).
- **Next.js (App Router) + TypeScript + Tailwind CSS**, 상태: Zustand(또는 React Context), 차트: 직접 SVG(프로토타입 방식) 또는 lightweight-charts
- 배포: **Vercel** 미리보기 → 이후 운영 환경

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1 | 6개 화면 + 모든 모달을 **가상 데이터(`data/`)**로 구현, 로컬 저장(localStorage) | 프로토타입과 화면·동작 동일, Vercel 미리보기 URL |
| 2 | 로그인, 규칙·매매일지·설정 서버 저장(예: Supabase/Postgres) | 새로고침·다른 기기에서도 유지 |
| 3 | 실시간 시세·재무·공시(DART)·뉴스 연동, 알림 발송 | 데이터 지연 감지·재계산 포함 |
| 출시 전 | 법률 검토 / 핀테크지원센터·금감원·금융위 사전컨설팅 | 자문·일임 신고 대상 여부 확인 |

**1단계부터 시작해 주세요.** 실데이터 연동은 범위 밖입니다.

## 정보 구조 (라우트 제안)
| 메뉴 | 라우트 | 핵심 |
|---|---|---|
| 홈 | `/` | 쓰는 순서 스테퍼, 오늘 손익, 들고 있는 종목, 내 조건 충족 종목 N(5개씩 ‹ › 페이징), 방금 온 알림 |
| 내 조건 충족 종목 | `/matches` | 좌측 목록(내부 스크롤) + 우측 상세(차트, 왜 조건에 맞았나요?, 내 계획 계산해 보기) |
| 알림 | `/alerts` | 공시·뉴스 소식 / 움직임 감지 / 내 규칙 / 보유 종목 필터 |
| 매매일지 | `/journal` | 기록할 게 있어요, 성적 요약, 기록에서 찾은 것, 매매 기록 표(펼침 상세) |
| 규칙 빌더 | `/builder` | 규칙 선택 레이어, 블록/수식/스크립트, 1~4단계, 미리보기, 규칙 점검 |
| 설정 | `/settings` | 화면(A/B), 원래 용어, 충족 종목 개수, 내 투자금, 알림 받기, 내 규칙 관리, 용어집, 약관·고지 |

**모달/레이어:** 첫 사용 안내, 조건 추가, 용어집, 규칙 수정, 산/판/안 샀어요 기록, 규칙 선택 레이어, 새 규칙 시작 패널, 토스트(6초 자동 닫힘).

## 레이아웃 공통
- **A 라이트**: 좌측 사이드바 232px(흰 카드, padding 28/14/22, sticky 100vh) + 메인. 사이드바 하단에 ‘지금 기준 규칙’ 셀렉트와 짧은 면책 문구.
- **B 다크**: 상단 바 64px(sticky, 하단 1px line) — 로고 · 가로 메뉴 · 우측 ‘기준 규칙’ 셀렉트.
- 메인: padding `28px 40px 56px`, 콘텐츠 `max-width:1240px`, 섹션 간 gap 18~20px.
- 헤더: 제목 28px/800/-0.03em, 부제 16px muted. 우측에 장 상태 pill(장 열림 13:02 / 장 마감 / 시세 지연).
- 카드: `border-radius:24px`, padding 24~28px, 배경 `card`. 카드 내부 박스 `sub` 배경, radius 14~18px.
- 2열 배치는 `flex-wrap` + `flex:1.35 1 480px` / `flex:1 1 340px`. 909px 폭에서도 가로 스크롤이 없어야 합니다.
- 모든 화면 하단 `<footer>`에 필수 고지(아래 참고).
- 숫자는 `font-variant-numeric: tabular-nums`. 한국어 줄바꿈은 `word-break: keep-all`.

## Screens / Views

### 1. 홈
1. **쓰는 순서 스테퍼**: 카드 안에 제목(13px muted ‘룰메이트 쓰는 순서’) + 상태 문구(17px/700 “3 / 7단계 · 다음은 ‘종목 확인’이에요”) + 우측 CTA(파란 버튼, 다음 단계 이동). 아래 7칸 grid: 24px 원(완료=파란 채움+✓, 현재=파란 테두리+4px priSoft 후광, 미래=회색 테두리) + 2px 연결선(완료 구간 pri, 나머지 off) + 13px 라벨.
   단계: 규칙 만들기 · 미리보기 · 저장 · 종목 확인 · 계획 계산 · 일지 기록 · 규칙 고치기.
2. **오늘 손익 카드**: 36px/800 금액(상승 빨강), 우측 ‘여유 있어요’ pill, 3개 미터(하루 손실 한도 · 연속 손실 · 오늘 매매, 6px 바). 1단계에선 값 고정 가능.
3. **들고 있는 종목 카드**: 종목명 20px, 수량·평균가, 평가손익(22px/800), 끊기~챙기기 가격 바(8px, 하락쪽 trackDown/상승쪽 trackUp, 현재가 16px 점), ‘팔았으면 기록하기’ 버튼. ‘계획만 세운 종목’ 행 + ‘샀어요’ 버튼. 없으면 빈 상태.
4. **내 조건 충족 종목 N**: 행 = 순위(17px pri) · 이름(16px/700) + 한 줄 이유(13px muted, ellipsis) · 점수 pill(priSoft) · 가격/등락. 5개씩, 우측 상단 ‘1–5 / 14’ + ‹ › + ‘전체 보기’. 상태: 로딩 스켈레톤 / 메시지 박스(미완성·오류·0개).
5. **방금 온 알림** 3건.

### 2. 내 조건 충족 종목
- 좌측 목록(flex 1 1 260px, max 340px, sticky top 88px, `max-height: calc(100vh - 110px)` 내부 스크롤): 헤더 ‘충족 N개 · 내 규칙 점수 순’, 카드(선택 시 2px pri 테두리) = 순위·이름·점수 / 가격·등락 / 한 줄 이유.
- 우측:
  - **차트 카드**: 시장·코드, 종목명 24px, 가격 32px/800. 선/캔들 토글, 데이터 상태 pill(실시간/3분 지연/종가). SVG 차트 48봉, 평균 단가(VWAP) 점선(보라), 조건 맞은 지점 마커(초록)·감점 지점(노랑) 라벨 pill, 끊기/살 가격/챙기기 수평선 + 우측 라벨, 거래량 막대.
  - **왜 조건에 맞았나요?**: ‘내 규칙 점수 85점 / 100’, 기여 막대(8px, 충족 조건별 세그먼트), 조건 행 = 28px 원 아이콘(✓ 초록 / ✕ 회색 / ! 노랑 / – 해당 없음) + 이름(+ 원래 용어 12px 회색) + 현재값·상태 단어·기준 + 점수.
  - **내 계획 계산해 보기**: 가격 계획 바 → 입력 3개(살 가격 / 손해를 끊고 팔 가격 / 이익을 챙기고 팔 가격, 각 54px 박스에 −/+ 40px 버튼과 호가 단위 증감) → 결과 박스(“내 손실 한도로 계산하면 최대 N주예요”, 필요 금액, 잘못되면/잘되면 금액 막대, 손익비 + 내 기준 통과/미달) → 진행 표시(계획 저장 · 산 기록 · 판 기록) → 버튼(상태별: 이 계획 일지에 저장 → 샀으면 기록하기 → 팔았으면 기록하기 → 매매일지에 기록했어요).
  - 투자금 미입력이면 수량 대신 “투자금을 넣으면 최대 수량을 알려드려요”.

### 3. 알림
- 필터 칩: 전체 / 공시·뉴스 소식 / 움직임 감지 / 내 규칙 / 보유 종목 + 우측 ‘알림 설정 ›’.
- 상시 안내(노랑): “뉴스는 주가가 먼저 움직인 뒤에 나오는 경우가 많아요…”
- 알림 카드: 태그(공시 소식·뉴스 소식=회색, 움직임 감지=노랑, 조건 충족=초록, 계획 가격=파랑, 시스템=회색) · 종목 · 등락 · 보유 중, 우측 ‘소식이 먼저 떴어요/주가가 먼저 움직였어요 · 시각’, 제목 18px/700, ‘쉽게 말하면 / 왜 알려드렸나요’ 박스, 출처, 액션 버튼.
- **호재/악재 판단 금지**: 공시·뉴스는 사실 요약만.

### 4. 매매일지
- **기록할 게 있어요**(대기 건수 배지): 계획 세움 행 → [안 샀어요][샀어요], 보유 중 행 → 지금 팔면 손익 + [팔았어요].
- 성적 4칸: 기록한 매매(진행 중·안 산 계획 수), 이긴 비율, 합계 손익, 규칙 지킨 비율.
- **기록에서 찾은 것**: 조건(예: 큰 내린 봉 감점)이 붙은 매매와 아닌 매매의 평균 비교 + ‘미리보기로 비교해 보기’(빌더로 이동, 해당 조건 하이라이트). 실서비스에선 최소 표본 수(예: 10번) 미만이면 결론 보류.
- 매매 기록 표 열: 날짜 · 종목 · 규칙·버전 · 그때 조건(14×6px 막대 줄 + “5/6개 충족 · 감점 ○○”) · 결과(수익률/손익, 진행 중) · 규칙 태그(지켰어요/어겼어요/보유 중/계획만/안 샀어요). 행 클릭 시 펼침: 차트(판 가격선 포함) + 가격 계획 바 + 계획/실제로 산 것/실제로 판 것 + 규칙 확인 3항목 + 메모 + 상태별 버튼.

### 5. 규칙 빌더
- **헤드 카드**: ‘편집할 규칙’ + **커스텀 선택 레이어**(46px 버튼: 이름 + 버전 태그 + ▼ → 펼침: ‘내 규칙 N개’, 각 항목 이름·상태 태그(미완성/수정 중/예시 필터)·버전·방식·저장 시각·✓, 하단 [+ 새 규칙][규칙 관리]) + 메타 텍스트 + [+ 새 규칙].
  - 새 규칙 패널: 빈 규칙 / 거래가 몰린 종목(예시) / 실적이 늘어난 종목(예시). 예시는 **숫자·점수 모두 비움** + “운영사가 성과를 보증하거나 권하는 규칙이 아니에요”.
  - 이름 입력(22px/800) + 공용 **[저장]** 버튼 하나(변경 없으면 비활성 회색, 저장 중… → 토스트 “v4로 저장했어요”). 고칠 곳이 있으면 저장하지 않고 토스트로 첫 오류 안내.
  - 방식 3카드: 블록(처음이라면) / 수식(엑셀이 편하다면) / 스크립트(코드가 편하다면).
- **1단계 종목 거르기 / 2단계 점수 매기기**: 블록 = 이름 칩 + 원래 용어 + 문장(앞말 [입력 ?][단위] 뒷말) + (점수 단계) 점수 입력(직접 입력 + −/+ 5점, 0이면 ‘점수’ 플레이스홀더, 감점은 음수) + ×. 범위 밖/빈칸이면 노랑 테두리 + 아래 오류 문구. ‘+ 조건 추가’ → 조건 추가 모달.
  - 수식 모드: 한 줄 입력 `평소보다북적임 >= 3`, 이름·형식 오류 안내.
  - 스크립트 모드: 코드 에디터(파이썬 `keep(s)` / `score(s)`), 린트(미래 참조 `shift(-1)` 등, `?` 빈칸), [블록 기준으로 되돌리기][미리보기에 적용].
- **3단계 마지막 확인 · 가격 계획**: 여기서 끊기(산 가격 % / 평균 단가 아래 / 따라 올라가기), 여기서 챙기기(걸 돈의 몇 배 / 산 가격 %) 세그먼트 + 숫자 행(끊기 폭, 벌 돈 배수 or 챙기기 폭, 걸 돈 대비 벌 돈·최소, 통과 기준 점수, 한 번에 잃어도 되는 돈) — **직접 입력 + −/+**, 범위 오류 표시.
- **4단계 알림**: 점수가 기준을 넘으면(점수 직접 입력) / 계획 가격에 닿으면 / 공시가 뜨면 — 스위치.
- **우측(sticky)**: 미리보기(지난 거래일 데이터: 샘플→거르기 통과→최종 충족, 상위 5개 막대+요약, 1위 차트) — 0개면 원인(가장 많이 걸러낸 조건)·완화 버튼. 규칙 점검 목록(오류/확인 필요/참고/통과).
- **조건 추가 모달**(max 840px): 검색, 7개 묶음 탭, 카드 = 이름 + 원래 용어(작게, 이름 옆) + 쉬운 설명 + “예시 · …”(12px 회색) + [+ 추가/추가됨]. 추가 시 **기준값·점수 모두 빈값**.

### 6. 설정
- 화면: A/B 미리보기 카드(라디오), 원래 용어 함께 보기 스위치.
- 내 조건 충족 종목 개수: 3/5/10/15 세그먼트 + 안내(“오늘 14개가 맞아서 위에서부터 10개를…”).
- 계산에 쓸 내 투자금: 56px 입력(우측 정렬 20px/800) + ‘원’ + × (누르면 비우고 포커스) + 빠른 칩(500만/1,000만/3,000만/5,000만). 계좌 연동 없음.
- 알림 받기: 3개 카드(점수 기준 — 점수 직접 입력, 계획 가격, 공시·뉴스). 바꾸면 즉시 적용, 규칙 버전 변화 없음.
- 내 규칙 관리: 행 = 이름·태그(미완성/예시 필터/지금 기준)·메타 + [수정][복제][삭제]. 삭제는 인라인 확인(“삭제할까요? 매매일지 기록은 남아요”), 마지막 1개는 삭제 불가. **[수정] → 규칙 수정 모달**(이름, 1·2단계 블록, 3단계 숫자, 점검 요약, [규칙 빌더에서 자세히][저장]). 닫으면 설정에 머물고 기준 규칙은 원래대로.
- 용어집: 제목·설명 + 우측 [용어집 열기] → 모달(검색, 7개 묶음 + 색의 뜻 탭, 카드 = 이름+원래 용어, 설명, 예시, 수식/스크립트 이름).
- 약관·고지: 필수 3문장 + ‘처음 안내 다시 보기’.

## Interactions & Behavior
- **저장/버전**: 결과 화면(홈·충족 종목·알림)은 **저장된 버전(saved)**만 사용. 빌더 미리보기는 draft 사용. 저장 시 version+1, saved=draft 복제.
- **규칙 전환**: 결과 화면에서 전환하면 650ms 로딩 상태 후 재계산.
- **기록 흐름**: plan(계획 저장) → hold(산 기록: 가격·수량, 빠른 버튼 ‘계획 가격/지금 가격’, ‘계획대로/절반’) → done(판 기록: ‘챙기기/끊기/지금’ 빠른 버튼, 손익 즉시 계산, 규칙 지킴 자동 판정, 한 줄 느낌·메모) / skip(안 샀어요: 이유 4개 중 택1). 판 기록은 전량 매도로 계산(분할 매도 범위 밖).
- **토스트**: 하단 우측 380px, 6초 후 자동 닫힘, 액션 버튼 선택.
- **첫 사용 안내 모달**: localStorage 키로 1회 노출, 설정에서 다시 보기.
- **0개/오류/지연/장 마감/미완성** 상태 문구는 프로토타입과 동일하게.

## 계산 규칙 (프로토타입 `class Component` 참고)
- 점수 = 거르기 통과 종목에서 맞은 조건 점수(감점 포함) 합. 통과 기준 점수 이상 & 손익비 ≥ 최소값만 표시, 점수 내림차순(동점 시 RVOL 큰 순), 설정 개수만큼.
- 거래 비용 0.23%(왕복) 항상 포함.
- 최대 수량 = floor( 투자금 × 위험% ÷ (살 가격 − 끊기 가격 + 살 가격 × 0.0023) ), 투자금/살 가격으로 상한.
- 끊기 가격: 산 가격×(1−끊기 폭) / VWAP×0.995 / 따라 올라가기(최고가 대비 끊기 폭). 호가 단위로 반올림(`tick()` 참고).
- 챙기기 가격: 살 가격 + (살 가격−끊기)×배수 / 살 가격×(1+챙기기 폭).
- 규칙 지킴: ① 산 가격 ≤ 계획+1% ② 수량 ≤ 계획 ③ 판 가격 ≥ 끊기×0.997 — 모두 만족.
- 규칙 점검: 빈칸, 범위 밖(`data/conditions.json`의 min/max), 주가 하한>상한 모순, 중복 조건, 점수 미입력/양수 조건 없음, 통과 기준>최고점, 조건 6개 초과(과최적화 경고), 수식 파싱 오류, 스크립트 미래 참조.
